name: 用户故事
description: 当需要为任意功能模块生成用户故事文档（Markdown 格式）时触发
---

## 执行前必读文件

```
docs/requirements/modules.md                        ← 模块标识目录（模块标识和路径的唯一来源，禁止自行创造模块标识）
docs/requirements/taskbrief/<模块标识>.md            ← 需求任务书（从目录中确认模块标识后读取对应文件）
docs/requirements/prototype/<模块标识>.html          ← 页面原型（UI 布局与视觉稿）
```

---

## 输入确认

开始生成前，必须确认以下信息（从模块目录和需求任务书中提取，如有缺失须向用户确认）：

| 确认项 | 说明 | 示例 |
| ------ | ---- | ---- |
| 模块中文名 | 功能模块的中文显示名称，须与模块目录中定义一致 | 段位维护 / 排行榜 / 题库维护 |
| 模块标识 | 用于文件命名和路径，**必须从模块目录（modules.md）中获取，禁止自行创造** | rank / leaderboard / question |
| 模块缩写 | 用于故事编号，取英文代号大写首字母 | Rank / Leaderboard / Question |
| 角色（As a） | 操作该模块的用户角色 | 一名管理员 / 一名学员 |
| 目标（I want to） | 对该模块的核心操作目标（查看/新增/编辑/删除等） | 对系统中的段位进行全生命周期管理 |
| 价值（So that） | 实现该目标的业务价值 | 灵活配置评分体系的段位规则 |
| 子功能列表 | 与操作入口一一对应（通常 3～5 个：列表/新增/编辑/删除） | 见 Step 2.3 |
| 关键业务规则 | 字段约束、唯一性、逻辑关系等 | 名称唯一、区间不重叠 |
| 不在范围内的功能 | 任务书中未纳入本版本的功能 | 批量操作、拖拽排序 |

---

## 执行步骤

### Step 1 — 从需求任务书提取故事要素

1. 先读取模块标识（`docs/requirements/modules.md`），确认模块标识在目录中已注册，并获取模块中文名与英文代号的对应关系
2. 再读取对应模块的需求任务书（`docs/requirements/taskbrief/<模块标识>.md`），提取以下信息：

| 要素 | 提取说明 |
| ------ | --------- |
| **角色（As a）** | 操作该模块的用户角色，与任务书保持一致 |
| **目标（I want to）** | 对模块中所有子操作的概括 |
| **价值（So that）** | 实现目标的业务价值 |
| **子功能数量** | 与操作入口一一对应（通常 3～5 个：列表/新增/编辑/删除） |
| **关键业务规则** | 字段必填性、唯一性、逻辑关系、关联约束等 |
| **不在范围内的功能** | 任务书中未纳入本版本的功能 |

---

### Step 2 — 生成用户故事文档

输出路径：`docs/requirements/story/user-story-{模块标识}.md`

#### 2.1 文件头部（基本信息表格）

```markdown
# US-{模块缩写}-01：{模块中文名称}

## 基本信息

| 项目 | 内容 |
|:---|:---|
| 故事编号 | US-{模块缩写}-01 |
| 模块 | {模块中文名称}（{模块标识}） |
| 优先级 | P0 |
| 状态 | 待开发 |
```

> 优先级默认 P0，如任务书中有标注则以任务书为准。

---

#### 2.2 用户故事描述（三段式）

```markdown
## 用户故事描述

**作为** `{角色}`，

**我想要** `{目标，包含所有子操作的概括}`，

**以便于** `{业务价值}`。
```

---

#### 2.3 功能范围概览表

列出本用户故事涵盖的所有子功能，格式：

```markdown
## 功能范围概览

本用户故事包含以下 N 个子功能：

| 子功能 | 操作入口 | 简要说明 |
|:---|:---|:---|
| **查看{实体名}列表** | 进入「{模块中文名}」页面自动加载 | 表格展示所有{实体名}记录（关键字段...、操作按钮） |
| **新增{实体名}** | 点击「+ 新增{实体名}」按钮 | 弹窗表单填写信息并创建 |
| **编辑{实体名}** | 点击行内「编辑」按钮 | 弹窗回显当前数据并修改保存 |
| **删除{实体名}** | 点击行内「删除」按钮 | 二次确认后移除该记录 |
```

> 子功能条目根据实际模块的入口和操作确定，不限于列表/新增/编辑/删除，可能包含搜索、导入导出、状态切换等。

---

#### 2.4 验收标准（每个子功能独立一节）

每个子功能包含三部分：**正常流程**、**异常流程**、**UI 交互说明**。

**正常流程格式：**

```markdown
#### 正常流程（Happy Path）

1. {角色} 执行 {触发动作}
2. 系统响应 {...}
3. {角色} 填写/确认 {字段/信息}
4. 系统完成 {操作} 并反馈 {成功提示}
```

规则：
- 步骤编号使用有序列表（`1. 2. 3.`）
- 每一步描述简洁，主语交替（角色/系统）
- 最后一步必须包含成功反馈（Toast 提示 + 刷新列表等）

---

**异常流程格式（表格）：**

```markdown
#### 异常流程

| 场景 | 系统响应 |
|:---|:---|
| {触发条件} | {前端/后端响应方式 + 提示文字} |
```

异常场景覆盖要求（对照任务书逐条填写，根据模块实际情况选择适用项）：

| 异常场景类型 | 适用条件 | 示例 |
| ------------ | -------- | ---- |
| 必填字段为空 | 模块有必填字段 | 前端即时校验 |
| 字段超长 | 模块有长度限制的字段 | 前端校验 |
| 数值关系非法 | 模块有数值型字段的大小关系约束 | 前端校验 |
| 名称/编号重复 | 模块有唯一性约束的字段 | 后端返回 400，提示具体原因 |
| 关联数据阻止删除 | 模块存在关联数据 | 后端返回 400，告知关联数量 |
| 并发删除/已不存在 | 模块有删除操作 | 后端返回 400，自动刷新列表 |
| 网络/服务不可用 | 所有模块 | 提供重试入口 |
| 权限不足 | 需要权限控制的模块 | 后端返回 403，提示权限说明 |

> 非所有异常场景都适用于每个模块，根据任务书中的业务规则选取适用项，禁止遗漏适用的异常场景。

---

**UI 交互说明格式：**

```markdown
#### UI 交互说明

- {布局说明：页面/弹窗中各区域的大致排布（如「上方搜索栏」「下方表格」「右侧操作列」）}
- {交互行为：点击/选中/切换等操作后系统的响应（如「点击行内编辑按钮→弹出编辑弹窗并回显数据」）}
- {弹窗规格：关闭方式、表单布局（如「弹窗支持点击遮罩或右上角关闭按钮关闭」「表单字段分两列排列」）}
- {操作按钮顺序：如「取消在左、确认在右」}
- {状态说明：Loading 状态、防重复提交、空数据提示等}
```

规则：

- **禁止**写入颜色代码、字号、像素间距等样式细节——这些已由 `docs/conventions/frontend/visual.md` 统一规定
- **只描述「在哪里」和「怎么操作」**，不描述「长什么样」
- UI 交互说明须参照原型文件（`docs/requirements/prototype/<模块标识>.html`）中的实际布局编写，但仅提取布局结构和操作逻辑，不搬运样式值

---

#### 2.5 范围外声明

```markdown
## 不在本故事范围内

- {不含功能 1} → {归属模块或原因}
- {不含功能 2} → {当前版本不支持}
- ...
```

常见范围外项（根据实际任务书调整，不限于以下内容）：

| 范围外项 | 原因示例 |
| -------- | -------- |
| 批量编辑/批量删除 | 当前版本不支持 |
| 拖拽排序 | 当前版本不支持 |
| 编辑历史/版本回溯 | 当前版本不支持 |
| 关联数据的级联业务处理 | 由后端规则决定 |
| 第三方集成 | 见对应集成模块 |
| 导入/导出 | 当前版本不支持 |

> 范围外声明必须覆盖所有任务书中未纳入本版本的功能，禁止遗漏。

---

### Step 3 — 细节规范

#### 3.1 编号规则

- 故事编号：`US-{模块缩写}-{序号两位数}`，如 `US-Rank-01`、`US-Question-01`
- 模块缩写取英文代号大写首字母，如：Rank / Exam / Score / Question

#### 3.2 角色命名

- 系统管理后台的操作者统称「一名管理员」
- 若有学员侧操作，角色改为「一名学员」
- 角色名称与需求任务书保持一致

#### 3.3 字段名称

- 文档中的字段标签使用中文（如「段位名称」「积分下限」）

#### 3.4 提示文案规范

| 类型 | 格式示例 |
|------|---------|
| 前端即时校验 | 「请输入{字段名}」/ 「{字段名}不能超过 N 个字符」 |
| 前端逻辑校验 | 「{字段A} 必须大于 {字段B}」 |
| 后端业务冲突 | 「{字段名}已存在」 / 「{字段名}与现有记录冲突」 |
| 成功 Toast | 「{操作对象}{操作动词}成功」，如「段位创建成功」 |
| 删除成功 Toast | 「{操作对象}已删除」 |

#### 3.5 删除确认弹窗文案

根据关联数据量 n 动态生成：

- 有关联数据（n > 0）：`确定要删除{实体名}「{名称}」吗？该{实体名}下当前有 {n} 条关联{关联对象名}，删除后相关{关联对象名}将受影响。`
- 无关联数据（n = 0）：`确定要删除{实体名}「{名称}」吗？此操作不可撤销。`
- 若模块无关联数据概念，统一使用：`确定要删除{实体名}「{名称}」吗？此操作不可撤销。`

---

## 禁止事项

- 禁止删除或覆盖已有的 `docs/requirements/story/` 目录下其他文件
- 禁止在未读取模块目录（modules.md）的情况下自行创造模块标识
- 禁止在未读取需求任务书的情况下凭空编写故事内容
- 禁止遗漏适用的异常流程场景
- 禁止正常流程最后一步缺少成功反馈
- 禁止范围外声明遗漏任务书中未纳入本版本的功能

---

## 文档样式要求

- 使用 `---` 水平线分隔各一级章节
- 子功能编号使用汉字：一、二、三、四
- 表格对齐使用 `:---`（左对齐），一致美观
- 流程步骤中系统行为使用冒号引导（如「弹出「新增{实体名}」模态框（Modal / Dialog），标题为「新增{实体名}」」）
- 强调文字使用 `**加粗**`，引用界面元素使用「书名号」，变量占位符使用 `{花括号}`
- 文件末尾不留空行
