## 执行前必读文件

```
docs/requirements/modules.md            ← 任务书目录（模块标识和路径的唯一来源，禁止自行创造模块标识）
docs/requirements/taskbrief/<模块标识>.md            ← 需求任务书（从目录中确认模块标识后读取对应文件）
docs/conventions/frontend/                           ← 前端设计规范，原型必须遵循
```

## 输入确认

开始生成前，必须确认以下信息（从需求任务书中提取，如有缺失须向用户确认）：

| 确认项 | 说明 | 示例 |
| ------ | ---- | ---- |
| 模块中文名 | 功能模块的中文显示名称，须与任务书目录中定义一致 | 段位维护 / 排行榜 / 题库维护 |
| 模块英文代号 | 用于文件命名和路径，**必须从模块目录（modules.md）中获取，禁止自行创造** | rank / leaderboard / question |
| 列表表格列定义 | 列标题、字段名、宽度、对齐方式 | 见 Step 2.2 |
| 新增/编辑表单字段 | 字段名、控件类型、校验规则 | 见 Step 2.3 |
| 业务校验规则 | 字段间的逻辑约束、唯一性约束等 | 见 Step 1 |
| 删除关联提示 | 删除时是否有关联数据提示 | 见 Step 2.4 |
| 预置示例数据 | 列表中展示的初始示例行数和内容 | 见 Step 2.2 |

## 执行步骤

### Step 1 — 从需求任务书提取业务要素

1. 先读取模块标识（`docs/requirements/modules.md`），确认模块标识在目录中已注册，并获取模块中文名与英文代号的对应关系
2. 再读取对应模块的需求任务书（`docs/requirements/taskbrief/<模块标识>.md`），提取以下信息：

**页面结构要素**：

- 列表页需要展示的字段（列标题、字段含义、对齐方式）
- 新增/编辑表单需要的字段（字段名、控件类型、校验规则）
- 是否需要搜索/筛选条件
- 删除操作是否有关联数据需要提示

**业务校验规则**（按实际模块调整）：

1. 各字段的必填性和唯一性约束
2. 数值型字段的取值范围和大小关系约束
3. 新增/编辑时的跨行校验规则（如区间不重叠、编号不重复等）
4. 删除时是否有关联数据需要提示
5. 列表默认排序规则

---

### Step 2 — 生成页面 HTML

输出路径：`docs/requirements/prototype/<模块英文代号>.html`

#### 2.1 页面整体布局

参照页面原型，页面结构如下：

```
内容卡片（白色卡片，带阴影）
  └─ {模块中文名}列表区
       ├─ 区块标题行：「{模块中文名}列表」标题文字（左对齐）
       ├─ 操作栏：[新增] 按钮（蓝色主按钮，左对齐，位于标题正下方、表格上方）
       ├─ 数据表格
       │    ├─ 列1～列N-1：业务数据列（按需求任务书定义列标题、宽度、对齐方式）
       │    └─ 列N：操作（居中，编辑链接 + 空格 + 删除链接）
       └─ 分页组件（参见 Step 3）
```

> **搜索区域**：若需求任务书中包含搜索/筛选条件，在操作栏与表格之间增加搜索区域：

```
       ├─ 搜索栏（位于「新增」按钮所在行右侧，右对齐）
       │    ├─ 搜索输入框/下拉选择框（按需求定义筛选字段）
       │    └─ [查询] 按钮 + [重置] 按钮
```

#### 2.2 数据表格规范

- 表头背景色：`#f5f5f5`，文字加粗
- 数据行：奇偶行交替或悬浮高亮（`hover` 时背景 `#f0f7ff`）
- 各列宽度根据字段内容合理分配，操作列固定约 160px
- 操作列包含「编辑」「删除」两个文字链接，颜色 `#1677ff`
- 无数据时显示「暂无数据」占位文本

**预置示例数据**：根据需求任务书提供 5～8 条示例数据，示例数据须符合业务规则（如排序要求、字段约束等）。示例数据应覆盖典型场景：

| 场景 | 示例数据要求 |
|------|------------|
| 正常数据 | 填写完整、符合所有校验规则的典型记录 |
| 边界数据 | 包含字段最大值/最小值/零值等边界情况 |
| 长文本数据 | 如有文本型字段，包含一条较长内容的记录以验证展示 |

#### 2.3 新增/编辑弹窗

触发方式：

- 点击「新增」按钮 → 弹出新增弹窗（标题「新增{实体名}」）
- 点击某行「编辑」链接 → 弹出编辑弹窗（标题「编辑{实体名}」，回填当前行数据）

弹窗表单字段：根据需求任务书逐一定义，每行格式为：

- **{字段中文名}** — 控件类型：{文本输入框 / 数字输入框 / 下拉选择框 / 日期选择器 / 文本域 / Emoji选择器等} — 校验：{必填/选填，格式约束，长度约束，范围约束，唯一性约束等}

**常见控件类型对照**：

| 数据类型 | 推荐控件 | 说明 |
|---------|---------|------|
| 短文本（≤50字） | 文本输入框 | 适合名称、编号等 |
| 长文本（>50字） | 文本域（textarea） | 适合描述、说明等 |
| 整数 | 数字输入框 | 适合数量、分数等 |
| 枚举值 | 下拉选择框 | 适合类型、状态等 |
| 日期/时间 | 日期选择器 | 适合时间相关字段 |
| 图标 | Emoji 选择器/图标选择器 | 适合图标类字段 |

弹窗底部操作：「取消」按钮（灰色）+ 「确认」按钮（蓝色主按钮）

**弹窗交互规范**：

- 编辑弹窗打开时自动回填当前行数据
- 弹窗宽度根据表单字段数量调整：字段 ≤ 4 个时宽度约 520px，字段 > 4 个时宽度约 680px
- 弹窗关闭时清空表单数据和校验状态
- 确认按钮在提交期间禁用（防止重复提交）

#### 2.4 删除确认弹窗

触发：点击某行「删除」链接

弹窗内容：
- 标题：确认删除
- 正文：根据是否有关联数据动态生成
  - 有关联数据时：`确定要删除{实体名}「{名称字段值}」吗？该{实体名}下当前有 {n} 条关联{关联对象名}，删除后相关{关联对象名}将受影响。`
  - 无关联数据时：`确定要删除{实体名}「{名称字段值}」吗？此操作不可撤销。`
  - 若模块无关联数据概念，统一使用：`确定要删除{实体名}「{名称字段值}」吗？此操作不可撤销。`
- 操作：「取消」+ 「确认删除」（红色危险按钮）

---

### Step 3 — 分页组件

分页栏固定显示在表格底部（即使总页数 ≤ 1 也必须显示），布局为左右两端分布：

**左侧（flex-start）：**
```
共 {total} 条    每页 [下拉框▼]  条
```
- 下拉选项：10 / 20 / 50 / 100，默认 20

**右侧（flex-end）：**
```
[‹]  [1]  [›]   前往  [输入框]  页
```
- `[‹]` 上一页按钮，当前为第 1 页时禁用（灰色）
- `[页码]` 当前页高亮显示（蓝色背景白字）
- `[›]` 下一页按钮，当前为最后一页时禁用（灰色）
- 跳转输入框宽度约 40px，回车或失焦时跳转

---

### Step 4 — 交互与状态

| 操作 | 触发方式 | 成功反馈 | 失败反馈 |
|------|---------|---------|---------|
| 新增 | 弹窗确认 | Toast「新增成功」+ 自动刷新列表 | 弹窗内联错误提示（校验未通过/名称重复/业务冲突等） |
| 编辑 | 弹窗确认 | Toast「编辑成功」+ 自动刷新列表 | 同上 |
| 删除 | 确认弹窗确认 | Toast「删除成功」+ 自动刷新列表 | Toast「删除失败：{原因}」 |
| 分页切换 | 点击翻页/跳转 | 列表内容更新，分页状态同步 | — |
| 搜索/筛选 | 点击查询/重置 | 列表内容更新，分页重置到第1页 | — |

> 若模块包含搜索功能，搜索栏的交互规则：
> - 点击「查询」按钮：携带筛选条件请求第 1 页数据
> - 点击「重置」按钮：清空所有筛选条件，重新请求第 1 页数据
> - 搜索输入框支持回车触发查询

## 禁止事项

- 禁止删除或覆盖已有的 `docs/requirements/prototype/` 目录下其他文件
- 禁止在没有二次确认弹窗的情况下直接删除数据
- 禁止前端校验缺失（必填、格式、范围、跨行约束等需逐一实现）
- 禁止分页栏在总条数为 0 或仅 1 页时隐藏
- 禁止「操作」列使用按钮组件（应为纯文字链接样式）
- 禁止在未读取需求任务书的情况下凭空设计页面结构
- 禁止预置示例数据违反业务校验规则
- 禁止自行创造模块标识（必须从模块目录 `modules.md` 中获取已注册的标识）
